## 1. Strategic context

- **First pilot target:** a **software development company** — the Phase 3C /
  v0.6 "first production pilot deployment." The developer-tools domain is the
  initial SSI manifest focus (50 pre-built manifests, dev-tools first), so the
  product's earliest deep competence aligns with this ICP.
- **Timing:** identification + early conversations happen during **Phase 3B**
  (v0.5; honest working estimate 16–22 months). A signed pilot + deployment is
  the **Phase 3C** transition gate (v0.6).
- **Deployment posture:** new customers begin in **Assisted mode** (Delphi
  proposes; a designated human reviews/approves). Autonomy is earned per task
  category as competence is demonstrated — this is an onboarding contract and a
  selling point, not merely a default.
- **Acknowledged uncertainty (CLAUDE.md "Honest acknowledgments"):** the
  first-customer sales execution path is uncertain; the solo-founder profile is
  an acknowledged risk; Phase 3C requires a funding source identified by the
  pilot-deployment transition.

## 3. Pipeline stages

```
Identified → Contacted → Discovery → Pilot-fit assessed → Pilot agreement → Deploying
```

- **Identified** — a real prospect named, with a stated reason they fit the ICP.
- **Contacted** — outreach made; awaiting or received first response.
- **Discovery** — active conversation to understand their workflows and fit.
- **Pilot-fit assessed** — go / no-go on whether they are the right *first* pilot.
- **Pilot agreement** — scope, reviewer, data boundaries, success criteria, and
  commercials agreed.
- **Deploying** — Phase 3C deployment + apprentice onboarding underway.

## 5. Apprentice onboarding readiness

What a pilot customer must provide for structured apprentice-style onboarding
(CLAUDE.md three-component architecture, component 3 — per-customer / per-user
specialization):

- [ ] Product context (what the company builds, and for whom)
- [ ] Documentation corpus (internal docs, runbooks, process descriptions) to ingest
- [ ] Process descriptions for the task categories Delphi will learn first
- [ ] A designated **human reviewer** for early Assisted-mode outputs
- [ ] Agreed data boundaries (Layer 3 personal / company content never leaves the
      deployment; Layer 1 / Layer 2 contribution opt-in status explicitly chosen)
- [ ] Per-task-category success criteria + escalation rules (what must escalate to a human)
- [ ] Cross-role knowledge-sharing configuration (defaults to per-user isolation;
      customer may opt into cross-role sharing)
