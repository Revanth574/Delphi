3. THE NEGATIVE CONTROL RETURNED `Unresolved` — outcome 3, a defect in MY FIXTURE
=========================================================================================

    daemon pgid 20203, ai comm "sai", 2640 samples
    census: [(20205, 'S', "delphi-runtimed")]
    last iteration: IterationEvidence { group_matches: [], before: [], after: [] }
    left: Unresolved   right: Topology

The expectation named this outcome before the run: *the fixture did not produce the input
it claims — a finding about the FIXTURE, not the control or the product.* That is what it
was.

**CAUSE, MEASURED: `exec` REPLACES `comm`.** A shell that `exec`s `sleep` has `comm=sleep`,
not `sh`. The shim was staged as `sai` and exec'd `delphi-stubborn-ai`, so it became
`delphi-stubborn` — and the probe, which discovers candidates by `comm`, never saw it
across 2640 samples. `before` and `after` are empty in every iteration.

**THE PART WORTH KEEPING: my mechanism test proved the wrong property.** It asserted the
shim's `ppid` and `pgid` and stopped — both true of a process the probe cannot find. The
property the CONSUMER needs is that the process stays findable, and I never asserted it.
Proving the property I thought mattered is not proving the one the consumer needs, and the
gap was invisible until an assembly run 140 seconds long spent every sample looking for a
name that no longer existed.

Fixed: the negative control now execs a file STAGED UNDER THE SAME NAME, so `comm` survives
the transition. The mechanism test now asserts `comm` after `exec` — RED-proven, a shim
that never execs fails it with `left: "delphi-detached"`.

**The negative control has still never produced a verdict.** `Topology` remains unobserved
in the assembly, and the question three `Reached` verdicts leave open is still open.
